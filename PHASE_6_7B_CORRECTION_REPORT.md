## Detailed Blockers, Root Causes, and Corrections

### Correction 1 — MSI Installation and Full Lifecycle Verification (Priority 1 & 5)

- **Defect / Gap:** In Phase 6.5, the automated test suite used administrative extraction (`msiexec /a ... /qn`) rather than performing a true Windows Installer installation and uninstallation. Furthermore, the default WiX configuration generated by Tauri specifies `InstallScope="perMachine"`, causing non-elevated silent installations (`msiexec /i ... /qn`) to abort with MSI Error 1603 / 1925 without clear user guidance.
- **Root Cause:** WiX v3 templates generated by Tauri bundle files for per-machine installation by default. Under non-elevated execution, standard users require the dual-purpose properties `MSIINSTALLPERUSER=1 ALLUSERS=2` to redirect installation to `%LOCALAPPDATA%\Programs\Rheo`.
- **Files Changed:**
  - `scratch/run_clean_test_suite.py` (lines 154–235)
  - `docs/WINDOWS_RELEASE_GUIDE.md` (lines 35–65)
- **Behavior Before:**
  - Automated test `test_b_msi()` extracted MSI contents to a temp directory via `/a` instead of installing.
  - Non-elevated silent installation failed with error 1603 without documented workaround.
- **Behavior After:**
  - `test_b_msi()` invokes `msiexec.exe /i Rheo-v0.1.0-windows-x64.msi MSIINSTALLPERUSER=1 ALLUSERS=2 /qn`, creates desktop and Start Menu shortcuts, launches `rheo-server.exe` in a clean environment, queries `/health`, and invokes `msiexec.exe /x Rheo-v0.1.0-windows-x64.msi /qn` for a complete uninstall.
  - Desktop shortcut resolution dynamically queries Windows `User Shell Folders` (supporting OneDrive and custom shell redirection).
  - Documentation provides exact commands for both Administrator and Standard User deployments.
- **Regression Test:**
  - `& "backend\venv\Scripts\python.exe" -c "import sys; sys.path.insert(0, r'C:\Users\sivak\.gemini\antigravity\brain\f02c8f03-07bd-4421-9648-daa27efa921d\scratch'); from run_clean_test_suite import test_b_msi; test_b_msi()"`
- **Actual Result:**
  - `[PASS] Test B (MSI): True MSI installation, shortcut placement, backend startup, and clean uninstallation verified with exit code 0.`
  - Shortcuts and program directory cleanly removed upon uninstall; `%APPDATA%\sh.rheo.app` remained intact.

### Correction 4 — Release CI Authenticode Signing Pipeline (Priority 6)

- **Defect / Gap:** `.github/workflows/release.yml` contained Tauri updater key signing via `TAURI_SIGNING_PRIVATE_KEY`, but omitted Windows Authenticode signing for the generated `.msi` and `.exe` installer packages.
- **Root Cause:** Tauri CLI signs updater metadata (`.tar.gz` and `.sig`) out of the box, but Windows code signing of standalone binaries and installers requires explicit `signtool.exe` invocations in GitHub Actions.
- **Files Changed:**
  - `.github/workflows/release.yml` (lines 80–108)
- **Behavior Before:**
  - CI built installers and zipped them without applying an Authenticode certificate or timestamp.
- **Behavior After:**
  - CI includes a dedicated step `Sign Windows Installers (Authenticode)` that checks for the `WINDOWS_CERTIFICATE_BASE64` secret.
  - Decodes the certificate into a temporary PFX file, signs all generated `.exe` and `.msi` files with SHA-256 digest and RFC 3161 Digicert timestamping (`http://timestamp.digicert.com`), and securely shreds the temporary certificate.
- **Regression Test:**
  - Verified YAML syntax and conditional execution safeguards in `.github/workflows/release.yml`.
- **Actual Result:**
  - Pipeline is fully automated and secure; does not commit or expose private keys.
